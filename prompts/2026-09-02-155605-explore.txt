● Right — that's deliberate, and it's a spec grey area worth a decision.

  Why it's currently like that

  The HTML in the brief ships all three <li> visible — no hidden, no
  display:none:

  <ul class="suggestions">
    <li>agile methodology</li>
    <li>agile methodology process</li>
    <li>agile methodology process testing</li>
  </ul>

  FR-02/FR-03 only describe what happens as you type ("if the typed characters
  match… remains visible… do NOT match… disappear"). With an empty field there
  are no typed characters, so nothing gets filtered out → all three stay. The
  fixture mirrors the brief's markup literally.

  But the spec never says which

  Most real autocompletes hide the list until focus or the first keystroke. The

● The fixture server takes config two ways: env vars at startup, or live via a 
  POST while it's running.

  Start it

  source .venv/bin/activate        # or prefix python with .venv/bin/

  python fixture/server.py
  # -> http://127.0.0.1:5057/autocomplete-form

  Option A — set config at startup (env vars)

  # match-anywhere filtering (FR-03) instead of the default prefix
  FILTER_MODE=anywhere python fixture/server.py

  # require a valid suggestion to be selected (rejects free text)
  REQUIRE_SUGGESTION=1 python fixture/server.py

  # both, and a different port
  FILTER_MODE=anywhere REQUIRE_SUGGESTION=1 PORT=5100 HOST=127.0.0.1 python
  fixture/server.py

  ┌────────────────────┬───────────────────┬──────────────────┐
  │        Var         │      Values       │     Default      │
  ├────────────────────┼───────────────────┼──────────────────┤
  │ FILTER_MODE        │ prefix | anywhere │ prefix           │
  ├────────────────────┼───────────────────┼──────────────────┤
  │ REQUIRE_SUGGESTION │ 0 | 1             │ 0                │
  ├────────────────────┼───────────────────┼──────────────────┤
  │ HOST / PORT        │ —                 │ 127.0.0.1 / 5057 │
  └────────────────────┴───────────────────┴──────────────────┘

  Reload the browser tab after starting — app.js reads the mode on page load.

  Option B — change it live (server already running)

  # see current config
  curl -s http://127.0.0.1:5057/api/config

  # switch to match-anywhere
  curl -s -X POST http://127.0.0.1:5057/api/config \
    -H 'Content-Type: application/json' -d '{"filter_mode":"anywhere"}'

  # turn on "must select a suggestion"
  curl -s -X POST http://127.0.0.1:5057/api/config \
    -H 'Content-Type: application/json' -d
  '{"require_suggestion_selection":true}'

  # back to defaults + clear the stored response
  curl -s -X POST http://127.0.0.1:5057/api/reset

  Again, reload the page after changing config.

  Inspect what a submission persisted

  curl -s http://127.0.0.1:5057/api/response/latest | python3 -m json.tool

  # force a broken payload (for eyeballing the negative cases)
  curl -s "http://127.0.0.1:5057/api/response/latest?inject=bad_locale"
